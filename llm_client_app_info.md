# Документация для разработки Клиентского Приложения (Flutter)

Этот документ содержит информацию, необходимую для разработки пользовательского приложения Sounduk.

## 1. Базовая информация

*   **Base URL (Dev):** `http://10.0.2.2:8000` (для Android эмулятора) или `http://127.0.0.1:8000` (для iOS симулятора / Web).
*   **Content-Type:** `application/json` (кроме загрузки файлов).

## 2. Аутентификация

В системе используется JWT (Bearer Token). Регистрация и вход происходят только по логину и паролю. Email не используется.

### 2.1 Регистрация
**POST** `/api/auth/register`

**Request Body:**
```json
{
  "username": "user123",
  "password": "strongpassword"
}
```

**Response (201 Created):**
```json
{
  "id": 1,
  "username": "user123",
  "created_at": "2023-10-27T10:00:00"
}
```

**Ошибки:**
*   `400 Bad Request`: "Пользователь с таким именем уже существует".

### 2.2 Логин
**POST** `/api/auth/login`

**Request Body:**
```json
{
  "username": "user123",
  "password": "strongpassword"
}
```

**Response (200 OK):**
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer"
}
```

**Важно:** Сохраните `access_token` в безопасном хранилище (SecureStorage) и добавляйте его в заголовок `Authorization: Bearer <token>` ко всем запросам ниже.

### 2.3 Получение профиля (Me)
**GET** `/api/auth/me`

Используется для проверки валидности токена и получения статуса аккаунта. В ответе приходят поля, которые не видны при обычной регистрации.

**Важно:** Этот эндпоинт **пока возвращает неполные данные** (только базовые поля `UserResponse`). Для полноценного отображения лимитов, пожалуйста, ориентируйтесь на ошибки API (403 при превышении лимита) или запросите у бэкенд-разработчика расширение модели ответа для `/me` (добавление `storage_limit`, `storage_used`, `is_premium`), если это необходимо для UI.

**Текущий Response (UserResponse):**
```json
{
  "id": 1,
  "username": "user123",
  "created_at": "..."
}
```

## 3. Треки

### 3.1 Загрузка трека
**POST** `/api/tracks/upload`

**Header:** `Content-Type: multipart/form-data`

**Body (Form Data):**
*   `file`: Файл (mp3, m4a, wav, flac).
*   `title`: String.
*   `artist`: String.
*   `album`: String (Optional).
*   `duration`: Int (в секундах).

**Ограничения:**
*   Пользователь имеет лимит хранилища (по умолчанию 1 ГБ).
*   Если файл превышает оставшееся место, сервер вернет ошибку.

**Response (201 Created):**
```json
{
  "id": "uuid-string",
  "title": "Song Title",
  "file_size": 5242880,
  ...
}
```

**Ошибки:**
*   `403 Forbidden`: "Превышен лимит хранилища" или "Недостаточно места. Лимит: X MB".
*   `403 Forbidden`: "Аккаунт ограничен" (если пользователь забанен).

### 3.2 Список своих треков
**GET** `/api/tracks`

Возвращает треки, загруженные текущим пользователем.

**Response:**
```json
{
  "tracks": [
    {
      "id": "uuid",
      "title": "Title",
      "artist": "Artist",
      "duration": 180,
      "file_size": 1048576,
      ...
    }
  ],
  "total": 1
}
```

### 3.3 Стриминг (Прослушивание)
**GET** `/api/tracks/{track_id}/stream`

**Важно:** Для авторизации стриминга нужно передавать токен **только через заголовок**, если используете кастомный плеер, который это позволяет.
Если вы используете стандартный плеер, который не поддерживает заголовки, используйте Query параметр:
`/api/tracks/{track_id}/stream?token=<access_token>`

Этот URL возвращает аудио-поток (`Range` requests поддерживаются для перемотки).

### 3.4 Удаление трека
**DELETE** `/api/tracks/{track_id}`

Удаляет трек и освобождает место в хранилище.

**Response:** `204 No Content`

## 4. Обработка ошибок и статусов

### Блокировка (`is_restricted`)
Если администратор заблокировал пользователя ("Аккаунт ограничен"), любой запрос с токеном этого пользователя вернет:
*   **Status Code:** `403 Forbidden`
*   **Detail:** "Аккаунт ограничен"

В этом случае приложение должно разлогинить пользователя и показать сообщение о блокировке.

### Лимиты хранилища
При загрузке файла следите за 403 ошибкой с текстом про лимит.
UI может (пока что) высчитывать занятое место самостоятельно, суммируя `file_size` из списка треков, так как `/me` пока не отдает `storage_used`.
